# Threat model

nimgrpc is a library: it runs inside the program of its user, as a gRPC client, as a server, or both. It holds no keys or data of its own except what TLS needs for a connection (the private key given by the program). What it protects is the program that links it.

## Assets

- The memory safety and availability of the process that embeds the server: a malformed request must not crash it, corrupt memory or make it allocate without bound.
- The confidentiality and integrity of the traffic when TLS is on (the keys are the program's; the library only uses them).
- The correctness of the gRPC status and of the data handed to handlers.

## Attackers and entry points

| Attacker | Entry | Mitigation | Residual risk |
|---|---|---|---|
| Unauthenticated network peer, server side | bytes of an HTTP/2 connection | nghttp2 (a maintained C parser, h2spec 135/146 passing, the rest justified in [h2spec.md](h2spec.md)) parses frames; the library only sees decoded events; connection errors send GOAWAY and close | a bug in nghttp2 or in the glue code; the C parts are built and tested under AddressSanitizer in CI |
| The same, gRPC layer | length-prefixed messages | `maxMessage` (4 MiB by default) bounds a message before it is buffered and after gzip decompression; a content-type other than `application/grpc` (alone or followed by `+` or `;`) gets HTTP 415 and a malformed `grpc-timeout` ends the call INTERNAL before the handler runs; the text of an exception a handler does not turn into a `GrpcError` is not sent to the client (UNKNOWN, "internal error"; `setErrorHook` gives it to the operator), so paths and queries do not leak | a message limit is per message, not per connection: many streams multiply it, up to `Limits.maxConcurrentStreams` (100 by default) times `maxMessage` |
| The same, Protobuf layer | message bodies | the decoder checks lengths and field numbers against the buffer and raises on malformed input ([../src/nimgrpc/protobuf.nim](../src/nimgrpc/protobuf.nim)); messages and groups nested deeper than `maxNestingDepth` (100) are refused, and groups are skipped without recursion; tests include malformed input and nesting bombs | none known (up to 0.3.0 nesting was bounded only by `maxMessage` and crashed the process) |
| A decompression bomb | gzip messages | decompression is capped at `maxMessage` | none known |
| Network attacker (man in the middle) | the connection | TLS 1.2 only, on BearSSL, with ALPN `h2` required on both sides (a client that offers no protocol is refused in the handshake, a server that selects none is refused by the client); only ECDHE key agreement with AES-GCM or ChaCha20-Poly1305 (no static RSA, CBC or 3DES); certificates with RSA keys of 2048 bits or more and no MD5 or SHA-1 signatures; the client trusts only the CA certificates it is given, checks the chain and the server name, and has no switch to turn that off; mTLS is available. Plaintext HTTP/2 is available for tests and trusted networks and says so | a program that chooses plaintext is exposed; the choice is the program's |
| A slow or stalled peer | open streams, unread data | per-stream and per-connection flow control (1 MiB per stream, reopened only as data is read, on both adapters; a blocking connection holds at most 8 MiB unread in all its streams), keepalive pings and their policy, deadlines (`grpc-timeout`), graceful shutdown | a connection that never finishes its handshake is closed after `Limits.handshakeTimeoutMs` (20 s); the system's TCP keepalive (`Keepalive.tcpSecs`, 15 s) finds a vanished peer; `Limits` (server): `maxConnectionAgeMs` and `maxConnectionIdleMs` (rotate old or idle connections, off by default), `maxConcurrentStreams` (100 by default), `maxConnections` (no limit by default: set one on a public server; the blocking server uses two threads per connection) and `maxConnectionBuffer` (16 MiB queued per connection); `maxConnectionsPerIp` and `maxCallMs` (off by default). On the blocking server a unary call uses a worker only once its message is there; a streaming call uses one for as long as it lasts, so a client that opens streaming calls and goes quiet holds workers until `maxCallMs` (set it), and `Health/Watch` and reflection are limited to 64 and 16 calls at once. A connection costs the blocking server two threads whatever it does: bound them with `maxConnections` and `maxConnectionsPerIp`, or use the chronos server. Responses a client asks for and does not read: the queues are bounded (256 KiB per stream, `maxConnectionBuffer` per connection), but each handler that waits to send keeps its own message and the encoded copy of it, so the memory is the number of handlers at once (blocking: at most `maxWorkers`, 256 by default; chronos: `maxConcurrentStreams` times the connections) times about twice the size of a response. Measured on 2026-11-15 (blocking server, release build, 200 calls asking for 4 MB responses and reading nothing): 1.76 GB, 8.8 MB per call; the allocator keeps that peak for later calls and does not give it back to the system. A server that answers strangers with large messages sets `maxWorkers`, `maxConcurrentStreams` and `maxConnections` for the memory it has, or sends large data in smaller messages |
| A misbehaving server, client side | replies | message limit, deadlines, cancellation, GOAWAY handling, reconnect with backoff | none known |
| A malicious `.proto` file | `protoc-gen-nim` input | the plugin runs at build time on files the developer chose; it writes Nim source | do not run it on proto files you do not trust, as with any code generator |
| A malicious dependency | nimble packages (`bearssl`, `chronos` and theirs) | few dependencies, pinned by minimum version in `nimgrpc.nimble`; see [security-policies.md](security-policies.md) | nimble has no lock file here; the user's program decides the exact versions |

## Out of scope

Authentication and authorization of calls beyond TLS and metadata: the library gives handlers the metadata, and the program decides. A server interceptor ([interceptors.md](interceptors.md)) is the place to decide once for every call, but it sees the metadata only and not the peer's certificate, and on the blocking server a unary call it refuses has already been received in full (up to `maxMessage`). With mutual TLS only clients with a certificate of the given CA connect, but a handler is not told which certificate it was. Rate limiting per client. Protection from a compromised host.

## Attack surface

The listening port of a server (HTTP/2 over TCP, optionally TLS); `protoc-gen-nim` (a build-time tool); nothing else: no files read at run time, no environment variables, no command line, no other sockets.
