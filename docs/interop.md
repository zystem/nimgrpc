# Interop

The cases come from the gRPC interop suite (`doc/interop-test-descriptions.md`
in grpc/grpc) and run over the shared `grpc.testing.TestService`.

- **Nim peer:** `tests/interop/interop.nim`, both server and client, written
  against code that protoc-gen-nim generated from grpc-proto's
  `grpc/testing/{empty,messages,test}.proto` (`tests/gen`, regenerated by
  `tools/gen_test_protos.sh`).
- **Reference peer:** `tests/interop/gopeer/main.go`, built on grpc-go v1.76.0.

## Results, 2026-10-31

Every direction passes in each mode (plaintext, TLS, mutual TLS); five runs in
a row gave the same result. TLS: BearSSL TLS 1.2 on the Nim side, Go's
crypto/tls on the other, ALPN h2, EC P-256 certificates from `tests/certs`.

Rejections across implementations:

- A grpc-go client without a certificate, against a Nim server requiring one:
  refused. grpc-go reports the handshake as failed with EOF.
- A Nim client without a certificate, against a grpc-go server requiring one:
  refused, with Go's fatal alert 42 (bad_certificate).

| Case | Nim → Nim | grpc-go → Nim | Nim → grpc-go |
|:---|:---:|:---:|:---:|
| empty_unary | pass | pass | pass |
| large_unary | pass | pass | pass |
| client_streaming | pass | pass | pass |
| server_streaming | pass | pass | pass |
| ping_pong | pass | pass | pass |
| empty_stream | pass | pass | pass |
| cancel_after_begin | pass | pass | pass |
| cancel_after_first_response | pass | pass | pass |
| timeout_on_sleeping_server | pass | pass | pass |
| status_code_and_message (unary and duplex) | pass | pass | pass |
| special_status_message | pass | pass | pass |
| unimplemented_method | pass | pass | pass |
| unimplemented_service | pass | pass | pass |
| custom_metadata (unary and duplex) | pass | pass | pass |
| client_compressed_unary | pass | pass | pass* |
| server_compressed_unary | pass | pass* | pass* |
| client_compressed_streaming | pass | pass* | pass* |
| server_compressed_streaming | pass | pass* | pass* |

\* grpc-go cannot report whether a message arrived compressed, and it
compresses a whole stream or none of it. So the Go peer cannot verify the
compressed flag on responses, and it sends every message of a compressed
client stream compressed. As a server it does not check `expect_compressed`,
so the Nim client runs against it with `--lenient-compression`, which skips the
probes and the checks that a message is *not* compressed. Nim to Nim runs
every check. The grpc-go client runs the probes against the Nim server, and
they pass.

Keepalive, beyond the official suite:

- A grpc-go client with keepalive (10 s, the minimum grpc-go allows) against an
  idle Nim server: the PINGs are acknowledged, and the connection stays READY.
- A Nim client pinging every 50 ms against a grpc-go server with the default
  enforcement policy: grpc-go sends GOAWAY too_many_pings, the open call fails
  with UNAVAILABLE, and the next call goes over a new connection
  (`interop client ... keepalive_enforced`).

## chronos peer, 2026-11-01

`tests/interop/ainterop.nim` runs the same cases on the chronos API, against
the async stubs generated with `--nim_opt=async`, plus `concurrent_load`
(2,000 unary calls and 100 server streams at once on one channel, from one
thread). Every combination passes in plaintext, TLS and mutual TLS:

| Client → server | Result |
|:---|:---|
| chronos → chronos | 19/19 |
| blocking → chronos | 18/18 |
| chronos → blocking | 19/19 |
| grpc-go → chronos | all pass, compression probes included |
| chronos → grpc-go | 19/19 with `--lenient-compression` (see above) |
| chronos → grpc-go, `keepalive_enforced` | pass: GOAWAY too_many_pings, UNAVAILABLE, then a new connection |

Not covered yet: the Google auth cases (they need Google credentials), and the
load-balancing and xDS cases.

## Running

```sh
nim c -d:release tests/interop/interop.nim
tests/interop/interop server 10010 &
tests/interop/interop client 127.0.0.1 10010
```

To build the Go peer, place `tests/interop/gopeer/go.mod.example` as `go.mod`
and run `go build`. With module proxy access, delete the `replace` block and
run `go mod tidy`. Without it, as in the sandbox where these results were
produced, point the `replace` lines at local clones of grpc-go, x/net, x/sys,
x/text, protobuf-go and go-genproto (googleapis/rpc).

Add `--tls` or `--mtls` to the Nim peer, and `-tls tls` or `-tls mtls -certs tests/certs` to
the Go peer, to run the same cases over TLS.

The chronos peer takes the same arguments:

```sh
nim c -d:release tests/interop/ainterop.nim
tests/interop/ainterop server 10012 &
tests/interop/ainterop client 127.0.0.1 10012
```

```sh
./peer -mode server -addr 127.0.0.1:10011 &
./peer -addr 127.0.0.1:10010              # grpc-go client against the Nim server
tests/interop/interop client 127.0.0.1 10011
```

## Health checking against grpc-go

`tests/interop/health_interop.sh` builds grpc-go's own health client (`tests/interop/gohealth`,
the official `grpc_health_v1` stubs) and `tests/interop/healthserver.nim` and runs the one against
the other: `Check` of the server and of a service, NOT_FOUND for a name nobody set, `List`, and
`Watch` of a name that is unknown at first (SERVICE_UNKNOWN), becomes SERVING, and turns
NOT_SERVING at `shutdown`. It needs Go 1.25 or later (grpc-go 1.84) and the module:
`GOTOOLCHAIN=go1.26.10 GOFLAGS=-mod=mod tests/interop/health_interop.sh`, with
`GOPROXY=off` if the module is in the local cache. Result (grpc-go 1.84.0, 2026-11-09): all
seven checks pass.
