# nimgrpc security reassessment and TLS recommendation

22 November 2026 · commit `66256710466564c8d0e344e37d5bb63f079b0e39` · Linux x86-64

**Release assessment.** The current TLS 1.2 transport is materially stronger than the revision reviewed on 21 November. It now gates application bytes on a persistent peer-verification decision, freezes configuration on use, and limits work waiting for a blocking worker. Two properties still need attention before relying on them in a capacity or key-handling policy: strict cross-connection memory admission and erasure of all intermediate private-key buffers. Neither finding establishes a remote key disclosure. [Previous assessment](SECURITY-REVIEW-2026-11-21.en.md)

## Findings and acceptance criteria

| Priority | Evidence and consequence | Recommended change and verification |
|---|---|---|
| High for tightly memory-limited services | The blocking adapter checks the shared retained-byte counter and later increments it in a separate operation. Different connection readers have different locks and can simultaneously observe sufficient space. Additional header blocks on a known stream are appended without charging their header weight. The advertised 256 MiB default is therefore an admission target, and the gauge can understate retained data. The code establishes the accounting gap. Its peak RSS impact was not measured. [Event handling and accounting](../../src/nimgrpc/h2/blocking.nim) | Reserve with a single atomic compare-and-exchange loop or under a shared admission lock. Charge each retained header block and body increment once, and release the reservation on dispatch, cancellation, reset and close. Use synchronized readers on several connections and include trailers while a call is queued. Assert that reservations never exceed the configured cap and return to zero. Report both retained logical bytes and process RSS. |
| Medium · key material in allocator memory | The PEM decoder explicitly wipes its final backing buffer. Its growth helper uses realloc, which may move a partially decoded private key and return the old allocation to the allocator without wiping it. Exploitation would require separate memory visibility, such as a process dump. The Linux wipe test wraps explicit free calls and searches for selected markers. It cannot establish erasure on allocator-internal relocation. [PEM buffer](../../src/nimgrpc/tls/gtls.c) · [Wipe test](../../tests/twipe.nim) | For secret buffers, allocate the larger block, copy, wipe the old block, then free. Check addition and growth for size overflow before allocating. Preserve the old buffer on allocation failure. Use a test allocator that forces movement and inspects the released storage with a multi-kilobyte key fixture. Document caller ownership of the original PEM string. |
| Deployment-dependent · service availability | Connections, per-IP connections, maximum call duration and streaming concurrency can be unlimited by default. The queued-byte budget excludes active workers, compression buffers and TLS buffers. A uniform per-IP cap behind a proxy can also penalize unrelated clients. [Limits](../../src/nimgrpc/h2/common.nim) · [Deployment guidance](../production.md) | Set limits from a process memory budget and intended stream lifetime. Reserve worker capacity for unary calls, expose queue gauges and refusal counters, and load-test mixed long streams and short calls. Acceptance criteria should include an RSS ceiling and unary p99 under sustained admission pressure. |
| Deployment-dependent · client identity and revocation | mTLS authenticates membership in a trusted CA domain. Handlers receive no verified certificate principal. The TLS 1.2 cache uses a ten-minute default and a resumed connection skips a new certificate check. Revocation checking is absent. [Production guide](../production.md) · [Session cache](../../src/nimgrpc/tls/gtls.c) | For per-client authorization, validate an application credential in an interceptor or expose a verified principal with defined full/resumed semantics. Never trust a client-supplied identity header on its own. Use separate trust domains and disable resumption where the required revocation interval is shorter than the cache lifetime. Test denial after a credential or policy change. |

## What changed since the earlier audit

- The low-level TLS API now distinguishes pending, verified and failed peers. Both plaintext entry points check this state. ALPN and verification failure are terminal. The latest connection destructor also releases the Nim-owned failure reason. [TLS wrapper](../../src/nimgrpc/tls/tls.nim)
- Configuration now freezes at first use or explicit sharing. Continue to build it on one owner thread before publication. The frozen flag is atomic, but its check does not serialize a setter already in progress against a concurrent first freeze. Document that precondition next to each public construction and sharing example. [Configuration lifecycle](../../src/nimgrpc/tls/gtls.c)
- The blocking queue now limits waiting calls and charges initial headers and arrived body data. Blocking and async streaming quotas have regression tests, including cases where unary calls need capacity. Protobuf now rejects overflowing tenth varint bytes. Keep these regressions alongside the new cross-connection accounting tests. [Queue tests](../../tests/tqueue.nim) · [Quota tests](../../tests/tquota.nim) · [Protobuf decoder](../../src/nimgrpc/protobuf.nim)

## Cryptography, timing and maintainability

The wrapper compares TLS 1.2 session identifiers with memcmp. Those identifiers are visible during the TLS 1.2 handshake. Possession of the master secret is established by the TLS engine. Replacing this comparison is a lower priority than correcting the private-key buffer lifecycle. Review the compiled cryptographic backend for each shipped CPU and compiler configuration. This review contains no independent constant-time measurement or certification of the underlying primitives. [Resumption decision](../../src/nimgrpc/tls/gtls.c)

Strengthen the allocation-failure test for the top-level configuration builder. The current loop computes whether an exception occurred and discards the result. Its final successful clean build cannot establish the response to each injected failure. Classify which allocations are required, assert failure for each required one, and verify the identity and trust policy of any permitted fallback. Update the opening C comment about threading to describe exactly which connection state is caller-serialized and which shared cache/configuration fields use internal synchronization. [Allocation tests](../../tests/tmemory.nim) · [C wrapper](../../src/nimgrpc/tls/gtls.c)

The TLS pump grows output by 16 KiB before checking how much data is ready, even on an empty poll. Profile allocations per RPC, first-byte latency, and throughput for both small unary calls and full-size streaming records. If empty polling is significant, expose the ready length or reuse a caller-owned buffer. Preserve the verification gate at the plaintext boundary. [Record and application pumps](../../src/nimgrpc/tls/tls.nim)

## TLS 1.3 choice under the MIT and size constraints

**Keep stock BearSSL for the current TLS 1.2 profile. Evaluate BearSSL-tls13 first for an opt-in TLS 1.3 profile.** The current wrapper explicitly sets both version bounds to TLS 1.2 and imports upstream BearSSL ABI modules. Moving to the fork requires matching headers, context layouts, linked objects and session semantics. A version-bound change alone is insufficient. Require h2 ALPN, certificate validation for DNS and IP names, mutual authentication, full and resumed handshakes, rekeying during long streams and both I/O adapters before enabling the profile. Supply the fork's clock and policy identifier when enabling tickets. [Current TLS setup](../../src/nimgrpc/tls/gtls.c) · [Fork reassessment](https://github.com/zystem/BearSSL/blob/master/SECURITY-REVIEW-2026-11-22.en.md)

The current stripped release example measured **658,904 bytes** with Nim 2.4.0, size optimization, static nghttp2 1.68.0 and dynamic libc and zlib. The previous report measured 650,712 bytes for the same example and linkage category, a difference of 8,192 bytes. This historical comparison does not isolate the cause. There is no measured TLS 1.3 binary-size winner for nimgrpc. Build the same example on the same pinned musl toolchain for the stock and candidate backends, and compare the total stripped ELF, peak RAM per connection and first-RPC latency. [Example](../../examples/static_client.nim) · [Static build recipe](../static-build.md)

CycloneSSL is available under GPLv2 or a commercial license. Its open-source edition does not meet the stated preference for a permissively licensed dependency. Consider the commercial edition only if its terms and measured footprint justify it. Keep OpenSSL as an independent interoperability peer. Picotls is another C candidate for a controlled footprint comparison, including its crypto backend. [CycloneSSL licensing](https://www.oryx-embedded.com/products/CycloneSSL) · [TLS WG implementation list](https://github.com/tlswg/tlswg-wiki/blob/main/IMPLEMENTATIONS.md)
