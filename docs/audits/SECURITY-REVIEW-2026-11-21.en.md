# nimgrpc audit and the choice of TLS 1.3

21 November 2026 · revision `3f257a1` (v0.7.0 + 10 commits) · Linux x86-64

**The choice for nimgrpc.** The project's criteria are a small final static client, keeping nimgrpc under MIT and no mandatory GPL dependency in the base build. Under these conditions I recommend **Mbed TLS in a minimal configuration, taking the Apache-2.0 option**, as the first independent candidate for production TLS 1.3. Keep BearSSL for the compact TLS 1.2 build. If the priority is the smallest size increase and the team is ready to maintain the protocol, **BearSSL-tls13** deserves the first comparative measurement, but it is too early to make it the production profile before the X25519 and resumption findings are closed. The exact winner on size will be known after the same Nim application is linked with both backends. [nimgrpc license](../../LICENSE) · [Mbed TLS and its licensing terms](https://github.com/Mbed-TLS/mbedtls#license) · [BearSSL-tls13 audit](https://github.com/zystem/BearSSL/blob/master/SECURITY-REVIEW-2026-11-21.en.md)

**Verdict on the current revision.** The standard transport is compatible with grpc-go over mTLS in both directions. The configuration explicitly limits a connection to TLS 1.2. The significant risks in the code that was read are tied to the queue of work, the lifecycle of the shared configuration and the keys, and the state of peer verification. Enabling TLS 1.3 does not by itself remove them. The Nim and C wrappers and selected paths of gRPC, HTTP/2 and protobuf were checked. The internals of nghttp2, BearSSL and the Nim compiler were not audited as a whole. [TLS profile](../../src/nimgrpc/tls/gtls.c) · [Threat model](../threat-model.md)

## Priority findings

1. **High for a blocking server reachable from outside — waiting work has no limit of its own.** In dispatchLocked, a task with headers is added to the shared queue before the check whether one more worker can be created. maxWorkers limits execution. Waiting tasks keep holding data and increase pending, and a closed connection is freed only when pending == 0. With the default maxConnections=0 and maxCallMs=0, long streaming handlers are especially sensitive to this behavior. The project already documents the memory cost of large responses; the queue needs a separate budget. Introduce maxQueuedCalls, refuse before a task is queued, release cancelled tasks and account for retained bytes, not only for the number of HTTP/2 streams. Until this is fixed, set the limits on connections, concurrent streams and call time from the memory of the particular service. Acceptance criterion: with a full pool the depth of the queue is bounded, and after cancellation memory and pending return to their base level. [Queue, workerLoop and reap](../../src/nimgrpc/h2/blocking.nim) · [Default limits](../../src/nimgrpc/h2/common.nim)
2. **High when a live configuration is changed — the immutability of TlsConfig rests on a convention.** share and the connections hold one C object; an atomic counter protects its lifetime. The public addTrustedCa and setIdentity can reallocate arrays that already configured TLS contexts point to. setIdentity appends the chain before it checks the new private key; an error can leave a partial change. A second successful call replaces key_mem without freeing the earlier allocation. This is a risk of a race, of an inconsistent identity and of a memory leak when keys are rotated through the setters. The published contract says to treat the configuration as immutable. Enforce the contract in code: builder → immutable config, or forbid the setters after publication. Check a new certificate/key pair as a whole first, then publish it atomically together with a new session cache. Test a repeated setter, a failed replacement and concurrent connections. [Nim API](../../src/nimgrpc/tls/tls.nim) · [gtls_conf_set_identity and the creation of connections](../../src/nimgrpc/tls/gtls.c)
3. **Medium — the low-level API remembers the start of a check as success.** checkPeer sets checked=true before it checks ALPN and gtls_peer_ok. After an exception, a second call on the same object skips both checks. The ordinary adapters treat the exception as a connection error; this audit did not establish a way around mTLS in the standard dial. For the public raw API and a future backend, make the states pending, verified and failed explicit. Give data to the application only in verified, and make failed irreversible. Add a regression test for a second check after a refusal. [checkPeer](../../src/nimgrpc/tls/tls.nim) · [Blocking](../../src/nimgrpc/h2/blocking.nim) · [Chronos](../../src/nimgrpc/h2/async.nim)
4. **Medium for the confidentiality of memory — the wiping of a TLS connection disappears in a release build.** The source of gtls_free calls memset before free. In the disassembled release binary of hsbench, the freeing of the certificate buffer is followed directly by the free of the connection itself. The server's session cache buffer is also freed without an explicit wipe. Reading these remains needs access to memory, for example through an independent read defect or a dump. Add a guaranteed wipe of the connection context, the cache buffer and the temporary copies of the private key, on error paths too. Check the optimized object code. The conclusion about the missing memset applies to gtls_free in the build that was checked. [gtls_free, cache_free and conf_destroy](../../src/nimgrpc/tls/gtls.c)
5. **Medium for the reliability of the C boundary — allocation failures in the PEM loader are not handled completely.** gbuf_sink discards the result of gbuf_add; a number of dupmem calls keep a pointer and a non-zero length without checking the allocation. This applies, for example, to the copying of the DER certificate and of the EC private key. The input here comes from the application's configuration. Add an error flag to the callback context, check every allocation and publish the structure only after parsing has finished. Test allocator failure step by step, keeping the previous working configuration. [PEM loader](../../src/nimgrpc/tls/gtls.c)
6. **Medium for decoder compatibility — the protobuf bounds check is incomplete.** getVarint limits the number of bytes, but on the last shift for uint64 it does not check that the significant part fits in the remaining bit. getTag checks for a zero field and the wire type, but not the upper bound of the field number, 2²⁹−1. Different components may interpret a malformed message differently. Move the checks before the shift and the type conversion; compare acceptance and refusal with protobuf-go on boundary values in debug and release. This is a conclusion from the code, with no claim of an out-of-bounds memory access. [Decoder](../../src/nimgrpc/protobuf.nim) · [Wire format](https://protobuf.dev/programming-guides/encoding/) · [Allowed field numbers](https://protobuf.dev/programming-guides/proto3/#assigning)

## Identity, leaks and constant time

- ALPN h2, chain and name verification, mTLS, limits on headers and on the decompressed message are useful properties of the current transport. The application's handler, however, does not receive the verified identity of the certificate. If different clients of one CA must have different rights, pass the interceptor an object of the verified peer with defined semantics on resumption. Do not accept client metadata as proof of identity. [Threat model](../threat-model.md) · [TLS API](../../src/nimgrpc/tls/tls.nim)
- The TLS 1.2 cache limits the time of resumption, ten minutes by default. A successful resumption proves possession of the secret of the earlier session; the certificate is not checked anew. For TLS 1.3, account explicitly for the ticket lifetime, the version of the mTLS policy, the server name and the original identity. An update of the trust anchors or of the mTLS requirements must invalidate the matching generation of the cache. [Session management](../../src/nimgrpc/tls/gtls.c) · [Security requirements](../security-requirements.md)
- In the C code that was read, memcmp is used for an OID, for an IP address in a public certificate and for the identifier of an offered TLS 1.2 session. These comparisons do not by themselves indicate a leak of the master secret. Signatures, AEAD and the Finished check are delegated to BearSSL. There were no timing measurements over sets of secret inputs and no hardware side-channel audit here. The latency benchmark below does not prove constant time. [C wrapper](../../src/nimgrpc/tls/gtls.c)

## Which TLS 1.3 implementation to choose

| Implementation | Decision for the project |
|---|---|
| **Mbed TLS** | The main candidate for a compact production build with TLS 1.3. The C implementation is configured at build time. Take the Apache-2.0 option and keep the licenses and notices of the dependencies, including the cryptographic component of the chosen release. This lets the nimgrpc sources stay under MIT. Set up one profile for client and server: ALPN h2, mTLS, DNS/IP checks, EC and the RSA certificates the project uses. Connect non-blocking I/O callbacks, and check partial writes and backpressure in chronos separately. The actual size of such a profile has not been measured here yet. [Mbed TLS](https://github.com/Mbed-TLS/mbedtls) |
| **BearSSL-tls13** | The closest path by API; the fork's license is permissive. According to the fork's published measurements, the text of a separate minimal C client grew from 116,625 to 130,859 B (+14,234 B), and that of a server from 111,839 to 125,647 B (+13,808 B). This is a good reason to include the fork in a measurement, but the increase for a final Nim client may differ. Conditions for admission: fix the findings on X25519, on the binding of resumption to mTLS and on key limits, check the nim-bearssl ABI and carry out an independent review of the fixes. [Sizes and method of the fork](https://github.com/zystem/BearSSL/blob/master/docs/testing.md) · [License of the fork](https://github.com/zystem/BearSSL/blob/master/LICENSE.txt) |
| **CycloneSSL** | Technically suited to embedded use and provides TLS 1.3, ALPN and I/O callbacks. The public edition is GPLv2, the alternative supply is commercial. MIT on the nimgrpc sources and the terms of distributing a statically linked application are different questions. For a standard distribution without GPL obligations and without a commercial contract, rule this option out. [Oryx terms](https://www.oryx-embedded.com/products/CycloneSSL.html) · [API](https://www.oryx-embedded.com/doc/tls_8h.html) |
| **picotls + minicrypto** | The protocol layer is MIT, but minicrypto has no verification of the peer's handshake signature. For the current requirements of server verification and mTLS, a verifier and chain checking would have to be added and maintained. The small size of one protocol layer does not give a comparable result. [Limitations of minicrypto](https://github.com/h2o/picotls#readme) |
| **OpenSSL / rustls-ffi** | Keep OpenSSL as an independent interop peer; there are no grounds to include it in the standard compact binary. rustls-ffi would require a separate static artifact and the Rust toolchain; for a project that already uses Nim and C, consider it when there is a comparable size measurement. [OpenSSL BIO](https://docs.openssl.org/3.5/man3/BIO_new_bio_pair/) · [rustls-ffi](https://github.com/rustls/rustls-ffi) |

**The measured BearSSL baseline.** On 21 November one and the same examples/static_client.nim was built from the checked commit on x86-64, Nim 2.4.0, nghttp2 1.68.0, release, opt:size, strip, without UPX. With dynamic libc and zlib: **650,712 B**. With static glibc and zlib: **1,651,152 B**, an ELF without a dynamic section; the linker warned about the getaddrinfo limitation in static glibc. These numbers describe two linkings with BearSSL. The most relevant reference point for a portable artifact is the **707 KB static musl client** that the authors report; that is a separate measurement by the project. [Application](../../examples/static_client.nim) · [musl recipe](../static-build.md)

**How to make the final choice.** For one commit of examples/static_client.nim, build three mutually exclusive profiles: the original BearSSL, BearSSL-tls13 and a minimal Mbed TLS. Keep the same musl, compiler, versions of nghttp2 and zlib, optimization flags, strip and set of functions. Do not pull the current bearssl/abi and its C objects into the build with Mbed TLS. The main metric is the bytes of the whole stripped ELF and the delta to BearSSL. Record separately the peak RAM per connection, the RSS with 100 connections and the latency of the first RPC. Count a result only after the client and the server pass h2, mTLS, DNS/IP SAN, refusals of a wrong certificate and both I/O models; do not reduce the size by turning off peer verification. The OpenSSL prototype below checks the I/O architecture and takes no part in the size comparison.

**Integration boundary.** Leave the choice of backend to build time and keep the interface of four buffers that blocking and chronos share. The configuration is immutable after publication. Until the chain, the name and ALPN are checked, the application gets no plaintext. In the initial profile, turn 0-RTT off: a general RPC may have side effects. Check the semantics of resumption when the mTLS policy changes and keys are rotated. [HTTP/2 over TLS](https://www.rfc-editor.org/rfc/rfc9113.html#section-9.2)

## What was run

- A clean archive of the revision, Nim 2.4.0, bearssl 0.3.1, chronos 4.4.1, Linux x86-64. The main series used a local static nghttp2 1.68.0; the project builds 1.71.0 in CI. The full standard nimble test finished with code 0: 27 programs, 305 OK results. In addition, with a freshly built nghttp2 1.71.0, 6 th2session checks and 29 ttls checks passed. Local sockets were provided for the network tests.
- A separate build of tests/ttls.nim with AddressSanitizer and useMalloc — **29 checks passed**, including EC/RSA, mTLS, ALPN and shared use of a configuration. The test uses the static nghttp2 built earlier, so the instrumentation coverage of the external libraries differs. A full TSAN, a long soak and a build on ARM were not part of this assessment.
- **Independent mTLS interop with grpc-go 1.76.0:** Go client → Nim server — 21 PASS each with blocking and chronos; Nim client → Go server — 18 and 19 PASS respectively. 79 results from four runs in total. In the direction towards Go the standard lenient-compression option was used. This is TLS 1.2 of the current library.
- **Check of a TLS 1.3 candidate:** the system OpenSSL 3.0.13 through Python ssl.MemoryBIO, the project's certificates, TLS 1.3 forced. A connection with name verification and data exchange, mTLS with a client certificate, refusal without the mandatory certificate and refusal on a wrong name all passed. In the positive cases both sides chose h2. This checks that the memory BIO model is applicable; a Nim binding, bounded BIO pairs and the 3.5 branch itself were not tried here. CycloneSSL and rustls were not included in this benchmark.

### Performance of the current implementation

The standard hsbench in release, loopback, 100 iterations per mode after warm-up. The measurement includes creating the channel, the first short RPC and closing; resumption is allowed where stated. Other checks were running on the machine at the same time. This is a reference point for repeating the measurement after integration, not tail latency statistics.

| BearSSL TLS 1.2 mode | Mean time |
|---|---:|
| Full handshake | 4.66 ms |
| Full mTLS | 5.24 ms |
| Resumption allowed, ordinary TLS | 0.48 ms |
| Resumption allowed, mTLS | 0.56 ms |

## What to add to tests and maintenance

1. A common matrix of TLS contracts for blocking and chronos: h2 required, EC/RSA chains, wrong DNS and IP SAN, unknown CA, mandatory mTLS, full and resumed handshake, closing during a handshake and refusal after a change of policy. For TLS 1.3 add KeyUpdate, receipt of a ticket after the handshake, partial writes and the absence of application bytes before authentication completes.
2. Deterministic OOM tests for the C wrapper and a check that certificate loading is atomic. A repeated call of a setter on a published object must have an unambiguous result. Complement ASan with a check for residual secrets in an optimized build.
3. Check the total memory budget and the length of the queue on a saturated worker pool. Record the number of waiting, cancelled and finished calls, and the time it takes to free closed connections. For streaming, choose separate quotas and deadlines by method type.
4. Remove the duplication of the plaintext admission logic and of the TLS state handling between the two adapters through a common, testable contract. Measure allocations and copies on the pullApp/pullRecords path before optimizing: both functions reserve a 16 KiB block before polling the engine. Compare a short unary call and a long stream first; changing the block size without these measurements may make one of the modes worse. [TLS pump](../../src/nimgrpc/tls/tls.nim)
5. Keep results separately by version of the TLS provider and nghttp2, Nim compiler, libc and CPU. Before a decision on embedded delivery, check static linking, dependency updates, independent compatibility and recovery after GOAWAY on the target platform.
